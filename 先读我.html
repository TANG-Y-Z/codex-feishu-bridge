先看这里：你需要准备什么

  • 一台 Windows 电脑，已安装并登录 Codex 桌面应用，能正常在本机项目里工作。只有 Codex CLI 或 IDE 扩展不够。
  • Node.js 24：从 Node.js 官网下载 Windows 安装程序，保留默认的 npm 和 PATH 选项。已安装该版本可跳过。
  • 自己的飞书账号，电脑和手机登录同一身份。你需要在自己的组织下创建应用，并有权限完成发布。
  • 把 ZIP 全部解压到固定目录，例如 D:\Tools\codex-feishu-bridge。不要从压缩包预览窗口直接启动。
没有小程序也完全可以用。本次分享的是文字指令和最终结果通知功能；不需要微信开发者工具、群聊、公网服务器或 OpenAI API Key。仍使用你自己的 Codex 登录与使用额度。

本工具不是 OpenAI 或飞书官方产品。已在一台 Windows 电脑跑通；它依赖 Codex 桌面自带的内部工具，不同版本可能需要适配。后面的连接检查用于确认你的电脑是否兼容。

先安装依赖

双击 1-安装依赖.cmd，等待窗口出现 Installation complete。这是安装程序需要用到的库，首次需要联网。看到失败提示时不要继续，先看本文末尾的排错说明。

双击文件对应的命令是 npm.cmd ci --ignore-scripts。若刚安装 Node.js 后仍提示找不到 node，请关掉该窗口重新双击。

1创建你自己的飞书机器人

  1. 打开 飞书开发者后台，使用自己的飞书账号登录。
  2. 选择 创建企业自建应用，名称可以填“Codex 手机助手”，描述可填“接收电脑 Codex 完成结果，并继续原对话”。
  3. 进入应用，在左侧 添加应用能力 中添加 机器人。
  4. 打开左侧 权限管理，点击开通权限，按下面的标识搜索并开通应用身份权限。
搜索这个标识权限名称 / 用途
im:message:send_as_bot以应用的身份发消息：机器人把结果发给你。
im:message.p2p_msg:readonly读取用户发给机器人的单聊消息：接收你发出的文字指令。

本次文字功能只需要这两项。没有小程序时不用开通 im:resource 图片资源权限。以后台当前名称为准，可用完整标识准确搜索。

不用建群。你将与自己创建的机器人一对一聊天。“飞书智能助手”等现成机器人不是本工具；群里的 Webhook 自定义机器人也不适用。

只有自己一个人的组织也可以尝试。若“飞书个人版”身份在创建或发布时受限，按飞书提示创建自己的团队；若属于公司的组织，需要管理员允许。最终以后台是否能完成发布、可用范围是否包含你为准。

2把 App ID 和 App Secret 填到本机

飞书开发者后台 → 你的应用 → 凭证与基础信息

  1. 找到 App ID 和 App Secret。这两个值必须来自同一个、由你创建的应用。
  2. 在解压后的文件夹中双击 2-填写配置.cmd。它会创建 .env 并用记事本打开；如果文件已存在，会保留原配置。
  3. 在等号右侧填入你自己的值。下面的文字只是格式示例，不能原样使用。
FEISHU_APP_ID=这里粘贴你自己的AppID
FEISHU_APP_SECRET=这里粘贴你自己的AppSecret

App ID 通常以 cli_ 开头。每项占一行，不要加中文引号或换行；复制时不要带前后的多余空格。以 # 开头的行是注释，保留即可。

  1. 按 Ctrl+S 保存，再关闭记事本。不要另存为 .env.txt。
只在自己的电脑上填写。不要把 App Secret 发给朋友或粘贴到 AI 聊天。朋友各自创建应用、使用自己的凭证；不要多人共用同一套 App ID / Secret。

文件里另外两项 WECHAT_… 是后续小程序实验功能的预留配置。本次保留默认值即可，无需安装相关软件。

3让自己的 Codex 生成本机连接配置

在 Codex 桌面应用里把解压后的这个文件夹打开为项目，然后在该项目聊天里粘贴下面这段话：

请配置这个飞书桥接项目与本机 Codex 的连接。先阅读 README.md，然后执行 npm run setup:codex，再执行 npm run doctor。飞书凭证我已在本机 .env 中填写，请不要读取或输出密钥，也不要把任何消息发到其他聊天。暂时不要替我启动常驻机器人，我会用启动文件手动启动。若连接信息不可用或工具不兼容，请说明具体原因，不要修改 Codex 安装文件来绕过。

成功时会生成 bridge.local.json，并看到类似“Codex 连接成功，检查到 N 个本地聊天”和“读取原聊天成功”的检查结果。

这一步必须在这个项目的 Codex 聊天里让 Codex 执行。直接在外部 PowerShell 运行 npm run setup:codex，可能取不到桌面应用提供的连接信息。不要复制朋友电脑上的 bridge.local.json。

以后重启或更新 Codex，连接地址可能会变。遇到连接失败时，先停止桥接，再重复这一步，最后重新启动。

4启动本机桥接，先别关窗口

双击 3-启动机器人.cmd。第一次成功启动时，窗口会显示：

Codex 已连接。正在连接飞书长连接……
首次绑定：在手机私聊机器人发送 /绑定 本次生成的绑定码
绑定码有效期 10 分钟。
飞书长连接已建立；可以回到开发者后台保存事件订阅。

看到“飞书长连接已建立”后，再做下一步。保持这个窗口打开，机器人需要它持续运行。若显示连接失败，先检查前面的配置；不要反复启动多个副本。

稍后绑定码若过期，可以双击“4-停止机器人.cmd”，等待启动窗口显示“机器人已关闭”，再重新启动获取新码。已绑定的账号重新启动不需要再次绑定。

5保存长连接事件配置并发布

飞书开发者后台 → 你的应用 → 事件与回调 → 事件配置

  1. 点击“订阅方式”旁边的编辑图标，选择 使用长连接接收事件 并保存。若提示“应用未建立长连接”，回到上一步确认本机程序仍在运行。
  2. 在 已添加事件 这一行右侧，点击蓝色 添加事件 按钮。
  3. 弹窗搜索 接收消息，选择标识为 im.message.receive_v1 的事件并添加。名称可能显示“接收消息 v2.0”，这是正常的。
  4. 确认“已添加事件”列表中能看到这项事件。如果提示缺少单聊权限，回“权限管理”开通上文的单聊消息权限。
只配“事件配置”，本版不用配置“回调配置”。文字消息走接收消息事件；目前没有卡片按钮回调。不需要填写公网回调地址。

然后发布

  1. 左侧打开 版本管理与发布，点击创建版本。
  2. 版本号可以填 1.0.0，更新说明填“接收文字指令并发送 Codex 结果”。
  3. 可用范围只选自己，保存并申请发布。若由你管理组织，可能自动审核通过；公司的组织可能需要管理员审批。
  4. 最终确认应用显示 已发布 / 已上线。之后更改权限或事件，也需要再次创建版本发布才能生效。

6在手机私聊绑定并验证

  1. 手机飞书切到应用所属的同一个组织身份，搜索你创建的机器人名称，例如“Codex 手机助手”，进入一对一私聊。搜索不到时也可从应用详情尝试“打开应用”。
  2. 把启动窗口里显示的 整条绑定指令发给机器人。不要发送示例文字，不要把别人的绑定码拿来用。
/绑定 这里换成本次启动显示的绑定码

收到“绑定成功”后，按顺序发送：

发给机器人应该看到什么
/状态“桥接运行中”。首次显示“当前聊天：未选择”是正常的。
/会话电脑上已有聊天的名称和编号。
/切换 2“已选择原聊天”。把 2 换成你实际想选的编号。
请只回复：手机控制测试成功。电脑的原聊天收到指令，手机稍后收到最终答复。

这四步都成功，才算完成整条链路验证。机器人只接受完成绑定的这个人的私聊，其他账号、群消息、机器人消息都会被忽略。

以后怎么开、怎么关、怎么继续对话

想做什么操作
在电脑上启动打开 Codex，再双击 3-启动机器人.cmd，保留运行窗口。已有绑定会保留。
坐在电脑前，暂时不想收推送手机发送 /静音，仍可给机器人发指令。
恢复自动结果通知手机发送 /通知，不补发静音期间的旧结果。
完全关闭手机发送 /关闭，或电脑双击 4-停止机器人.cmd。之后需要回电脑才能重启。
切换默认聊天先 /会话，再 /切换 编号。后续直接发文字会进入选中的原聊天。
针对某条结果继续提要求在飞书长按那条结果，选择回复再发文字，只将这条指令发回对应聊天。
主动看当前聊天最近的结果/结果
忘记了命令/帮助
多个聊天会同时通知。假设默认选了对话 2，又收到对话 1 的结果：直接输入文字仍发给对话 2；引用对话 1 的结果回复，才会发给对话 1。引用回复不会改变默认选择。

电脑需要保持联网、不休眠，Codex 与桥接都运行。本包没有开机自动启动。关闭桥接不会关闭 Codex，也不会中断已经交给 Codex 的工作。

如果任务停在权限审批，需要在桌面 Codex 或 官方 Codex Remote 中处理。此版不会自动替你同意审批。手机图片、语音、附件暂不处理。

常见问题

绑定码过期，或者发了绑定指令没反应

绑定码从每次启动起有效 10 分钟。先停止并重新启动生成新码，再发完整指令。如果仍没反应，检查应用是否已发布、事件是否包含 im.message.receive_v1、两项权限是否生效、机器人可用范围是否包含自己，以及是否用同一组织身份私聊。

显示“应用未建立长连接”

先填好自己的凭证、完成 Codex 配置并启动本机程序，看到“飞书长连接已建立”后，再回后台保存事件配置。配置先后顺序不能颠倒。

机器人搜索不到，或者没有聊天输入框

确认不是“待上线”，检查应用发布、机器人能力、接收消息事件和可用范围。切换到该应用所属的飞书组织身份，稍后重新打开应用。若已改过权限或事件，要重新发布。

npm / node 找不到，或者依赖安装失败

安装 Node.js 24，并重新打开窗口。依赖下载需要联网；安装失败时保留错误提示，排查网络后重新执行“1-安装依赖.cmd”。如果 PowerShell 提示 npm.ps1 不允许运行，可用 npm.cmd 替代 npm，不必改系统执行策略。

Codex 连接失败，或者 setup:codex 缺少连接信息

确保打开的是支持本机工具的 Codex 桌面应用。把这个桥接文件夹作为项目，让该项目里的 Codex 执行连接配置和 doctor。若提示找不到 codex-app-tools 或所需工具，说明当前安装不兼容；先检查应用和工具是否可用，不要复制别人的连接配置或修改安装文件绕过。

重启电脑 / Codex 后机器人不能用了

打开 Codex，先停止旧桥接，在本项目聊天里让 Codex 重新执行 npm run setup:codex 和 npm run doctor，成功后再双击启动。自己的绑定记录会保留。

显示机器人已经运行，或者我开了多个启动窗口

先双击“4-停止机器人.cmd”，等原运行窗口显示关闭后再启动一次。每个应用只运行一个本工具实例，避免多个实例分走手机消息。

找不到旧聊天 / 停机时发出的消息没有补处理

列表检查最近 50 个非置顶本地聊天及全部置顶聊天，也会持续检查手动选过的聊天。旧聊天先在桌面打开或置顶，再发 /会话。重新启动会跳过停机期间的指令和旧通知，这是避免过时指令突然执行的设计。

提示指令可能已送达，或状态里出现待核对指令

网络超时后不能确定 Codex 是否已收到指令，程序不会自动重发。先打开原聊天核对，再决定是否发送新指令。

帮助里有 /预览，我需要配置吗

不用。这是后续小程序功能预留代码，真实项目尚未联调，不属于本次已验证能力。不用小程序时忽略它和 WECHAT_… 配置即可。

哪些文件不能再转发给别人

本包只含代码、空白模板和说明。运行后，下列文件会包含你自己的数据：

文件内容
.env你的飞书凭证。
bridge.local.json你这台电脑的 Codex 连接信息。
.data/绑定用户、手机指令、未送达结果和引用定位记录。
*.log、.cache/、artifacts/运行日志、缓存和生成文件。

再次分享时转发原始 ZIP，不要压缩自己运行过的整个文件夹。正常聊天内容经 Codex 处理；手机指令和被转发的最终答复还会经过飞书。运行目录应只由你信任的人访问。

本版本固定依赖并附测试源码。已验证的是原电脑的文字收发流程；你的环境要按上述步骤自测。更详细的运行边界和维护者打包方式见同目录 README.md。
